1. Что это за приложение и какие у него границы#

Это консольная модель доставки товаров. Покупатель регистрируется, входит, смотрит каталог, оформляет заказ, условно оплачивает его и получает назначенного курьера. Можно посмотреть историю, завершить доставку и отменить ещё не оплаченный заказ.

Программа создаёт четыре товара и двух курьеров при старте. Все пользователи и заказы находятся в оперативной памяти в ArrayList. После закрытия программы они исчезают. База данных, интернет, платёжные системы, карты и GPS не используются.

В одном заказе только один вид товара, но количество может быть больше одного. Например: «Мышь × 2». Это сознательное упрощение учебного проекта.

Требования исходного задания#

Задание требует как минимум 10 осмысленных классов, регистрацию и вход, основную операцию, историю, Scanner, исключения и принципы ООП. В этой версии 12 классов + 1 enum (перечисление не считаем обычным классом). Main только запускает приложение. В коде есть abstract, extends, @Override, ссылки между объектами и try/catch/throw/throws.

2. Как запустить#

  1. В IntelliJ IDEA: File → Open → папка DeliverySystem_Explained.
  2. Выбрать JDK 17 или 21: File → Project Structure → Project → SDK.
  3. Если src не отмечена как исходники: правой кнопкой по src → Mark Directory as → Sources Root.
  4. Открыть src/delivery/Main.java, нажать зелёную кнопку около main() → Run.
  5. Внизу во вкладке Run вводить пункты меню и подтверждать их Enter.

При желании через терминал из папки проекта:

javac -encoding UTF-8 -d out src/delivery/*.java
java -cp out delivery.Main

javac компилирует файлы .java в .class, java запускает указанный класс. delivery.Main означает «класс Main из пакета delivery».

5. Каждый Java-файл: назначение и все методы#

5.1. Main.java — точка входа#

Зачем нужен: запускает программу; в нём намеренно нет регистрации, поиска товара и оплаты.

  • public static void main(String[] args) — первый метод, с которого Java начинает выполнение. Создаёт new ConsoleApp() и вызывает .start(). Параметр args здесь не используется.

Связь: Main использует ConsoleApp. Если хочется понять, откуда всё начинается, всегда открывайте Main.java.

5.2. ConsoleApp.java — меню и ввод#

Зачем нужен: этот класс «разговаривает» с пользователем, но сам не решает, разрешено ли платить, хватает ли товара или кому принадлежит заказ. Это проверяют сервисы.

Поля:

  • scanner — читает строки из консоли.
  • authService — объект для регистрации и входа.
  • storeService — объект с логикой заказов.
  • currentCustomer — вошедший покупатель; null, если никто не вошёл.
  • running — флаг, управляющий циклом меню.

Все методы:

Метод Что делает, с кем работает
ConsoleApp() Конструктор. Создаёт 4 Product, 2 Courier и передаёт их в StoreService.
start() Печатает заголовок. В цикле показывает одно из двух меню. Перехватывает AppException через catch и продолжает работать.
showLoginMenu() Меню регистрации, входа, завершения программы. Выбор через switch.
register() Спрашивает имя, логин, пароль, адрес; вызывает authService.register(...).
login() Спрашивает логин и пароль; вызывает authService.login(...), сохраняет currentCustomer. Показывает полиморфизм через Person person = currentCustomer.
showMainMenu() Меню после входа: каталог, заказ, история, оплата, доставка, отмена, выход из аккаунта.
showProducts() Проходит по товарам из storeService.getProducts() и выводит ID, название, цену, остаток.
createOrder() Запрашивает номер товара и количество, вызывает storeService.createOrder(...), печатает результат.
showOrders() Получает storeService.getHistory(currentCustomer) и выводит только свои заказы.
payOrder() Запрашивает номер заказа, вызывает storeService.payOrder(...), выводит курьера. Полиморфизм через Person person = delivery.getCourier().

completeDelivery() Передаёт номер заказа в storeService.completeDelivery(...).
cancelOrder() Передаёт номер заказа в storeService.cancelOrder(...).

readNumber(String prompt) Вызывает readText, пробует Integer.parseInt, а при неправильном вводе выдаёт AppException.

Почему readNumber() читает строку, а не scanner.nextInt()? Чтобы избежать типичной проблемы смешивания nextInt() и nextLine() с оставшимся символом Enter. Весь ввод читается через nextLine(), числа преобразуются отдельно.

Важно: showMainMenu() и showLoginMenu() объявляют throws AppException, но внутри start() эта ошибка перехватывается и превращается в понятную строку, а программа не закрывается.

5.7. OrderItem.java — содержимое заказа#

Поля: product, quantity, priceAtOrder.

Метод Назначение

Почему отдельный класс? Товар — самостоятельная вещь в каталоге; позиция заказа — сведения о том, сколько этого товара купили в конкретном заказе. Класс OrderItem — часть объекта Order, что демонстрирует композицию.

5.8. OrderStatus.java — состояние заказа#

Это enum, а не обычный класс. Он содержит три значения:

  • NEW — заказ создан и ещё не оплачен;
  • PAID — оплата условно подтверждена;
  • CANCELED — заказ отменён до оплаты.

Состояние «Доставлено» не входит в OrderStatus. Его возвращает Delivery.getStatus() на основе поля delivered. Поэтому доставленный заказ продолжает иметь OrderStatus.PAID: это особенность этой упрощённой модели, а не ошибка запуска.

Метод Назначение

5.11. AuthService.java — регистрация и авторизация#

Поля: customers — список покупателей; nextId — следующий номер пользователя.

Метод Назначение
register(name, login, password, address) Проверяет непустые поля, ищет занятый логин через equalsIgnoreCase, создаёт Customer, добавляет в список и возвращает его. Ошибка: пустое поле/занятый логин.
login(login, password) Перебирает пользователей, проверяет логин и checkPassword(), возвращает найденного Customer; иначе ошибка «Неверный логин или пароль».

Зачем nextId++? При первом создании покупателя используется ID 1, затем переменная увеличивается до 2. При следующей регистрации выдаётся новый номер.

Почему после регистрации надо отдельно войти? register() создаёт аккаунт, но ConsoleApp.currentCustomer заполняется только методом login().

5.12. StoreService.java — правила магазина#

Самый важный класс для защиты: связывает товары, покупателя, заказ и курьера, но не показывает меню.

Поля: products — товары, orders — все заказы, couriers — курьеры, nextOrderId — следующий номер заказа, nextCourierIndex — индекс курьера.

Метод Назначение

getProducts() Возвращает новый список с теми же объектами Product; это не полная копия каждого товара.
findProduct(int id) Перебирает каталог, находит товар по ID либо выдаёт ошибку.
createOrder(customer, productId, quantity) Находит товар → уменьшает склад через reduceStock → создаёт Order → сохраняет в список → возвращает заказ.
getHistory(Customer customer) Перебирает все заказы и отбирает только те, где order.getCustomer() == customer.
findMyOrder(customer, id) Ищет заказ одновременно по номеру и владельцу. Чужой заказ не выдаёт.
payOrder(customer, orderId) Проверяет свой заказ и статус NEW, берёт очередного курьера, выполняет order.pay(), создаёт Delivery, привязывает к заказу.
completeDelivery(customer, orderId) Находит свой заказ, проверяет наличие доставки, вызывает Delivery.complete().
cancelOrder(customer, orderId) Находит заказ, вызывает Order.cancel(), возвращает товар на склад через Product.returnStock().

Как выбирается курьер? По очереди: индекс 0, индекс 1, снова 0. Выражение (nextCourierIndex + 1) % couriers.size() берёт остаток от деления и возвращает индекс в начало списка. Это не поиск свободного курьера и не расчёт оптимального маршрута.

Почему история не показывает чужие заказы? ConsoleApp передаёт текущего currentCustomer; StoreService проверяет, что объект покупателя в заказе — тот же объект. В этой программе объект покупателя после входа берётся из AuthService, поэтому сравнение ссылок == здесь работает корректно.

5.13. AppException.java — понятные ошибки#

  • AppException(String message) — конструктор, который передаёт текст ошибки через super(message) в стандартный Exception.

Пример: если в Product.reduceStock(999) остатка не хватает, создаётся AppException. Метод StoreService.createOrder() передаёт ошибку дальше; ConsoleApp.start() ловит её в catch и печатает Ошибка: Недостаточно товара на складе.... В результате приложение остаётся открытым.

                         extends          extends

Стрелки — упрощённая схема того, кто кого использует или хранит. Для защиты важнее правильно объяснить смысл каждой связи, чем направление стрелки.

6.1. Наследование#

Customer extends Person, Courier extends Person: «покупатель — это человек», «курьер — это человек». Оба наследуют getName() и getInfo(), но каждый по-своему реализует getRole().

6.2. Полиморфизм#

Person person = currentCustomer; // Внутри — Customer.
System.out.println(person.getInfo());

Person courierPerson = delivery.getCourier(); // Внутри — Courier.
System.out.println(courierPerson.getInfo());

Оба раза используется тип Person, но getInfo() вызывает правильный getRole() в зависимости от реального типа объекта. @Override находится в Customer.getRole() и Courier.getRole().

6.3. Ассоциация#

Order хранит Customer customer — заказ связан с покупателем. Если удалить отдельный заказ из истории, покупатель как сущность не исчезает. Покупатель может быть связан с несколькими заказами.

6.4. Агрегация#

StoreService получает уже созданные Product и Courier через конструктор. Эти объекты существовали до создания сервиса, и смысл их существования не зависит от того, хранит ли сервис ссылки на них. Это агрегирующая связь в учебной модели.

6.5. Композиция#

В Order выполняется this.item = new OrderItem(product, quantity);. Позиция заказа создаётся внутри конкретного заказа и по смыслу является его частью. В Java это демонстрация композиции по устройству модели; язык сам по себе не запрещает вернуть ссылку на OrderItem через getter.

6.6. Зависимость#

ConsoleApp использует методы AuthService для входа и регистрации: без этого сервиса интерфейс не сможет выполнить нужные действия. Ещё пример: метод StoreService.createOrder() временно использует переданный ему Customer и вызывает метод Product.reduceStock().

Не путать: наследование отвечает на вопрос «является ли одним из видов?», композиция — «является ли частью?», зависимость — «использует ли возможности другого класса?».

7.2. Оформление заказа на две мышки#

До заказа у «Мыши» цена 6000 тг и остаток 10. В меню вводим ID 1 и количество 2.

ConsoleApp.createOrder()
  -> StoreService.createOrder(currentCustomer, 1, 2)
     -> findProduct(1) -> Product «Мышь»
     -> Product.reduceStock(2) -> остаток 10 - 2 = 8
     -> new Order(1, customer, product, 2)
        -> new OrderItem(product, 2)
        -> status = OrderStatus.NEW
     -> orders.add(order)
  -> вывод: заказ №1, сумма 12000 тг, статус NEW

Самая полезная строка для объяснения: Order order = new Order(...) создаёт заказ, а orders.add(order) сохраняет его в историю на время работы программы.

7.3. Условная оплата и назначение курьера#

ConsoleApp.payOrder()
  -> StoreService.payOrder(currentCustomer, orderId)
     -> findMyOrder(...) — проверить владельца
     -> проверить статус NEW
     -> выбрать очередного Courier из couriers
     -> Order.pay() -> статус PAID
     -> new Delivery(order, courier) -> «В пути»
     -> Order.setDelivery(delivery)
  -> ConsoleApp печатает имя курьера и статус доставки

Важно: реальной оплаты нет. Программа лишь имитирует подтверждение платежа и назначение курьера.

7.4. Отмена и восстановление склада#

ConsoleApp.cancelOrder()
  -> StoreService.cancelOrder(currentCustomer, orderId)
     -> найти заказ владельца
     -> Order.cancel(): только NEW -> CANCELED
     -> Order.getItem()
     -> Product.returnStock(quantity)

Если заказ уже PAID, Order.cancel() выбросит AppException до возврата товара, то есть склад не увеличится ошибочно.

     -> перебрать orders
     -> отобрать заказы указанного Customer
  -> вывести номер, товар, количество, сумму, статус

8. Исключения: try, catch, throw, throws#

Ситуация: пользователь вводит не число, а abc вместо количества.

  1. ConsoleApp.readNumber() получает текст abc.
  2. Integer.parseInt("abc") вызывает стандартный NumberFormatException.
  3. В блоке catch (NumberFormatException e) он преобразуется в throw new AppException("Введите целое число.").
  4. Метод имеет throws AppException, поэтому передаёт ошибку выше.
  5. ConsoleApp.start() ловит AppException, печатает сообщение и снова показывает меню.

Другая ситуация: покупатель хочет 999 мышек, но на складе 10. Product.reduceStock() сам создаёт AppException. Ошибка проходит через StoreService.createOrder() и ConsoleApp.createOrder() до общего catch в start().

Отличать:

  • throw — выбрасывает конкретную ошибку из текущего места;
  • throws — объявляет в заголовке метода, что он может не обработать ошибку сам;
  • try — выполнить код с риском ошибки;
  • catch — перехватить ошибку и выбрать, что делать дальше.

10. Самые вероятные вопросы и понятные ответы#

1. Зачем здесь 12 классов, а не 5 из названия темы?
Пять классов в теме — примеры. В общем задании требуется минимум 10 осмысленных классов. Мы отделили интерфейс, авторизацию, заказ, товар, доставку и обработку ошибок.

2. Где ООП, а не просто последовательность println?
Каждый объект хранит свои данные и методы. Например, Product отвечает за склад, Order за статус заказа, Delivery за факт доставки. Интерфейс использует эти объекты через методы.

3. Зачем два сервиса AuthService и StoreService?
Один решает задачи пользователей, другой — заказы и товары. Так один класс не становится огромным.

4. Почему Person абстрактный?
Он нужен как общее описание человека, но реальными участниками системы являются покупатель и курьер. У них разный getRole().

5. Почему Customer наследуется от Person, а Order — нет?
Покупатель — разновидность человека, а заказ не является человеком. Заказ связан с покупателем, но не наследует его.

6. Почему у Order есть OrderItem?
OrderItem хранит сведения о товаре в этом конкретном заказе: какую позицию купили, количество и цену на момент покупки.

7. Где исключения и зачем они?
Product.reduceStock() выдаёт ошибку при нехватке товара; AuthService.login() — при неправильном пароле. ConsoleApp.start() ловит их и не закрывает приложение.

8. Почему используется ArrayList, а не база данных?
Задача учебная, нужно показать взаимодействие объектов. Данных немного, поэтому достаточно простых списков. После закрытия всё исчезает — это известное ограничение.

9. Почему доставка в истории оплачена, даже когда доставлена?
OrderStatus хранит состояние оплаты/отмены заказа, а Delivery отдельно хранит признак завершения. В более крупной системе можно было бы сделать расширенную схему состояний.

10. Что бы вы улучшили, если бы было больше времени?
Сохранение в БД, безопасное хранение паролей, корзину с несколькими товарами, настоящие роли курьеров, обработку платёжных статусов и проверку занятости курьеров.

/**
 * AuthService — регистрация и вход покупателей.
 * Сервис НЕ печатает меню и НЕ читает Scanner: это работа ConsoleApp.
 * Данные хранятся в ArrayList в оперативной памяти до выхода из программы.
 */
public class AuthService {
    // Список всех зарегистрированных покупателей.
    private ArrayList<Customer> customers = new ArrayList<>();
    private int nextId = 1; // Номер следующего нового покупателя.

    /**
     * Создаёт нового пользователя и запоминает его.
     * @param name имя
     * @param login логин для входа
     * @param password пароль (в учебной модели обычная строка)
     * @param address адрес доставки
     * @return созданный объект Customer
     * @throws AppException пустые поля или занятый логин
     */
    public Customer register(String name, String login, String password, String address)
            throws AppException {
        // Нельзя регистрироваться с пустыми полями.
        if (name.isEmpty() || login.isEmpty() || password.isEmpty() || address.isEmpty()) {
            throw new AppException("Заполните все поля.");
        }
        // Проверяем, нет ли пользователя с таким логином.
        for (Customer customer : customers) {
            // equalsIgnoreCase позволяет считать anna и ANNA одним логином.
            if (customer.getLogin().equalsIgnoreCase(login)) {
                throw new AppException("Такой логин уже существует.");
            }
        }
        // nextId++ выдаёт текущий номер, затем увеличивает его на 1.
        Customer customer = new Customer(nextId++, name, login, password, address);
        customers.add(customer); // Добавляем в память приложения.
        return customer;
    }

    /**
     * Ищет покупателя по логину и паролю.
     * @return найденный Customer, если данные правильные
     * @throws AppException если пара логин/пароль не найдена
     */
    public Customer login(String login, String password) throws AppException {
        for (Customer customer : customers) {
            if (customer.getLogin().equalsIgnoreCase(login)
                    && customer.checkPassword(password)) {
                return customer; // Успех: сразу выходим из метода.
            }
        }
        // Цикл закончился — подходящего аккаунта нет.
        throw new AppException("Неверный логин или пароль.");
    }

package delivery;

import java.util.ArrayList;

/**
 * StoreService — основная бизнес-логика магазина.
 * Работает с товарами, заказами и доставками, не печатает меню.
 * ConsoleApp спрашивает у пользователя, ЧТО сделать, а StoreService
 * определяет, МОЖНО ли это сделать и как изменить данные.
 */
public class StoreService {
    // АГРЕГАЦИЯ: товары и курьеры созданы в ConsoleApp и переданы сюда.
    private ArrayList<Product> products = new ArrayList<>();
    // Здесь же храним уже созданные заказы.
    private ArrayList<Order> orders = new ArrayList<>();
    private ArrayList<Courier> couriers = new ArrayList<>();
    private int nextOrderId = 1;       // Следующий номер заказа.
    private int nextCourierIndex = 0;  // Индекс следующего курьера (с нуля).

    /**
     * Принимает готовые списки товаров и курьеров.
     * addAll копирует элементы списка (ссылки на те же объекты), а не
     * создаёт заново каждый Product или Courier.
     */
    public StoreService(ArrayList<Product> products, ArrayList<Courier> couriers) {
        this.products.addAll(products);
        this.couriers.addAll(couriers);
    }

    /**
     * Отдаёт копию СПИСКА товаров для отображения в меню.
     * Сами объекты Product остаются теми же (не глубокая копия).
     */
    public ArrayList<Product> getProducts() {
        return new ArrayList<>(products);
    }

    /**
     * Находит товар по номеру ID.
     * @return Product, если такой товар существует
     * @throws AppException если ID не найден
     */
    public Product findProduct(int id) throws AppException {
        for (Product product : products) {
            if (product.getId() == id) {
                return product;
            }
        }
        throw new AppException("Товар с таким номером не найден.");
    }

    /**
     * Создаёт заказ указанного покупателя.
     * Шаги: найти товар -> проверить склад -> создать Order -> сохранить.
     * @param customer текущий авторизованный покупатель
     * @param productId ID товара из каталога
     * @param quantity количество единиц товара
     * @throws AppException если товара нет, либо неверное количество
     */
    public Order createOrder(Customer customer, int productId, int quantity)
            throws AppException {
        Product product = findProduct(productId);
        product.reduceStock(quantity); // Проверяет остаток и уменьшает его.
        Order order = new Order(nextOrderId++, customer, product, quantity);
        orders.add(order);             // Без этой строки заказ не появится в истории.
        return order;
    }

    /**
     * Возвращает историю заказов ТОЛЬКО указанного покупателя.
     * Сравнение == здесь корректно: после входа используется тот же объект
     * Customer, который ранее добавлен в AuthService.
     */
    public ArrayList<Order> getHistory(Customer customer) {
        ArrayList<Order> history = new ArrayList<>();
        for (Order order : orders) {
            if (order.getCustomer() == customer) {
                history.add(order);
            }
        }
        return history;
    }

    /**
     * Находит свой заказ по номеру и одновременно проверяет владельца.
     * Чужой заказ открыть нельзя, даже если известен его номер.
     */
    public Order findMyOrder(Customer customer, int id) throws AppException {
        for (Order order : orders) {
            if (order.getId() == id && order.getCustomer() == customer) {
                return order;
            }
        }
        throw new AppException("Заказ не найден в вашей истории.");
    }

    /**
     * Учебная оплата: никакого банка и списания средств здесь нет.
     * Находим заказ, проверяем его состояние, выбираем курьера по очереди,
     * отмечаем заказ оплаченным и создаём Delivery.
     */
    public Delivery payOrder(Customer customer, int orderId) throws AppException {
        Order order = findMyOrder(customer, orderId);
        if (order.getStatus() != OrderStatus.NEW) {
            throw new AppException("Оплатить можно только новый заказ.");
        }
        if (couriers.isEmpty()) {
            throw new AppException("Нет доступных курьеров.");
        }
        // Например, есть два курьера: берём 0-го, затем 1-го, затем снова 0-го.
        Courier courier = couriers.get(nextCourierIndex);
        // % — остаток от деления. Не даёт выйти за границы списка.
        nextCourierIndex = (nextCourierIndex + 1) % couriers.size();

        order.pay(); // Меняем OrderStatus.NEW на OrderStatus.PAID.
        Delivery delivery = new Delivery(order, courier);
        order.setDelivery(delivery); // Связываем заказ с доставкой.
        return delivery;
    }

    /**
     * Завершает доставку данного заказа.
     * Если заказ не оплачен, объекта Delivery ещё нет, поэтому будет ошибка.
     */
    public void completeDelivery(Customer customer, int orderId) throws AppException {
        Order order = findMyOrder(customer, orderId);
        if (order.getDelivery() == null) {
            throw new AppException("Сначала нужно оплатить заказ.");
        }
        order.getDelivery().complete();
    }

    /**
     * Отмена до оплаты: меняем статус заказа, возвращаем количество на склад.
     * Проверка «заказ ещё NEW?» находится внутри Order.cancel().
     */
    public void cancelOrder(Customer customer, int orderId) throws AppException {
        Order order = findMyOrder(customer, orderId);
        order.cancel(); // Если статус не NEW, будет AppException.
        OrderItem item = order.getItem();
        item.getProduct().returnStock(item.getQuantity());
    }
}

15 популярных вопросов преподавателя#

  1. Что такое класс? Шаблон, который описывает данные и поведение объекта. Например, Product.
  2. Что такое объект? Конкретный экземпляр класса: new Product(1, "Мышь", 6000, 10).
  3. Что такое конструктор? Метод инициализации объекта, который вызывается при new.
  4. Что такое инкапсуляция? Поля private, доступ к ним через методы. Склад меняется через reduceStock, а не прямым присваиванием.
  5. Зачем getters и setters? Читать и контролируемо изменять приватные поля.
  6. Что такое наследование? Customer и Courier получают общие поля и методы из Person.
  7. Что такое абстрактный класс? Общая основа, экземпляр которой напрямую создать нельзя. Person требует определить getRole().
  8. Что такое полиморфизм? Переменная типа Person может ссылаться и на Customer, и на Courier. getInfo() вызовет подходящий getRole().
  9. Для чего @Override? Показывает, что метод переопределён в наследнике; компилятор проверяет корректность.
  10. Чем ассоциация отличается от композиции? Покупатель живёт независимо от заказа (ассоциация). OrderItem создаётся как часть конкретного Order (композиция в модели).
  11. Что такое агрегация? Магазин хранит ранее созданные объекты товаров и курьеров; они могут существовать отдельно от него.
  12. Что такое зависимость? Один класс пользуется возможностями другого, например ConsoleApp вызывает AuthService.login().
  13. Зачем try/catch? Чтобы ошибка ввода не завершала программу, а давала понятное сообщение.
  14. Разница throw и throws? throw создаёт и выбрасывает конкретное исключение; throws у метода сообщает, что ошибка может быть передана вызывающему коду.
  15. Почему данные пропадают после закрытия? Они хранятся в ArrayList в оперативной памяти, без файлов или базы данных.

Краткое объяснение для преподавателя

Я разработал консольную учебную систему доставки товаров на Java.
Покупатель может зарегистрироваться, войти в аккаунт, посмотреть каталог,
создать заказ, условно оплатить его, узнать назначенного курьера,
посмотреть историю заказов и статус доставки. Неоплаченный заказ можно
отменить — тогда товар возвращается на склад.

Программа состоит из 12 классов и одного enum. Класс Main запускает
ConsoleApp, который отвечает за меню и Scanner. Авторизация находится
в AuthService, а основная логика магазина — в StoreService. Классы
Product, Order, OrderItem и Delivery описывают объекты предметной области.

В проекте продемонстрированы основные принципы ООП:
- инкапсуляция: private-поля и getters/setters;
- наследование: Customer и Courier наследуют Person;
- абстракция: abstract class Person и метод getRole();
- полиморфизм: объекты Customer и Courier используются как Person;
- переопределение: @Override у getRole();
- ассоциация: Order связан с Customer;
- агрегация: StoreService хранит переданные товары и курьеров;
- композиция: Order создаёт внутри себя OrderItem;
- зависимость: ConsoleApp вызывает методы AuthService.

Ошибки (неверный пароль, отсутствие товара, неправильный ввод,
обращение к чужому заказу) обрабатываются через AppException,
try/catch, throw и throws. История хранит заказы конкретного покупателя.

Это именно учебная модель: данные находятся в оперативной памяти,
поэтому после закрытия программы не сохраняются. Оплата условная,
а завершение доставки отмечается вручную через меню. Базы данных,
банковской интеграции и GPS нет. Эти упрощения позволили сделать код
понятным и сосредоточиться на взаимодействии классов и принципах ООП.

Для демонстрации я могу создать пользователя, выполнить вход с верным
и неверным паролем, оформить заказ, оплатить его, показать курьера,
статус доставки, историю и обработку ошибки.
